## risks
- Duplicate API clients: adding role and membership endpoints only to core/api/adminApi.ts leaves App.vue and PermissionGrantEditor.vue on the top-level copy. adminApi.test.ts would keep passing against the wrong file.
- Feature tests vi.mock the entire core adminApi, so backend contract changes (new DTOs, 404 vs 403, 409 body) won't break any frontend test unless a core client contract test is added.
- Removing the '*' wildcard from frontend can() without another master-admin signal hides everything from master-admin in DeviceCommandModal, because master-admin appears only as '*' (MeController.cs:35-36).
- Passing a real subject to AppShell (instead of the SUPER_ADMIN default at AppShell.vue:39) makes nav fail closed. During bootstrap, and for any link that later gets a permission field, users see an empty or reduced menu. Since app/nav.config.ts has no permission fields today, nothing gets hidden until they are added.
- The global PolicyVersion used for optimistic concurrency (DevicePermissionsController.cs:172) will cause frequent false conflicts if it is reused for role and membership edits across orgs.
- App.vue's production script opens a second SignalR hub connection and runs duplicate fetches alongside DeviceDetailView. Revocation and eviction handling therefore lives in two places (App.vue:148-152, DeviceDetailView.vue:268-272).
- DeviceDetailView keys the device off listDevices('').find(...). Once members only see devices with device.view, a direct URL to a hidden device renders a half-populated page with fallback telemetry instead of a 404 or 403 state.
- The /admin/roles-permissions grant flow probably fails today (no CSRF token: RolePermissionView.vue:23) while the backend requires antiforgery. Replacing it is low-regression, but not confirmed by running.
- Brand: primary buttons use Tailwind v4 oklch orange, not exact #f97316/#ea580c, and shade order differs between components (primitive: 600 base/500 hover; DeviceDetailView anchor: #f97316 base/#ea580c hover). In light theme --color-primary is undefined, which affects tab underlines (border-[var(--color-primary)], DeviceDetailView.vue:498 etc.) and PermissionGrantEditor's button.
- LoginView redirects to '/overview' by default (LoginView.vue:49), which is not a defined route (routes.ts:15 is /monitoring/overview), so it lands on not-found. Not caused by permissions, but any guard-based redirect work will run into it.

## open_questions
- Will the backend add an endpoint for the current user's effective permissions on one device (e.g. GET /api/v1/devices/{id}/my-permissions, or a field on the device DTO)? And will it return identity info (user id, isMasterAdmin, org id)? None exists today: MeController exposes only permissions and command-catalog, and AuthController only csrf/login/logout.
- Should /api/v1/me/permissions keep returning '*' for master-admin, or return an explicit flag the UI can use for the bypass and for showing high-risk permissions?
- Where should the Device roles library live: replace the content of /admin/roles-permissions (RolePermissionView, dropping PermissionGrantEditor), or a new org-scoped route such as /admin/organizations/:orgId/device-roles? How does a sub-org admin pick or see their org(s)?
- Should DevicePermissionsTab (the membership editor) be hidden from users without permissions.manage on the device's org, or shown read-only?
- Will the command catalog's featurePermission carry the manifest permission code (e.g. gpio.do_write)? For config.get/config.set, where the permission depends on payload data.domain, how should the modal know the required permission before submit?
- What 404 and 403 response bodies (codes) will the new endpoints return, so the client can show distinct states? Should adminApi switch to core/http/errors.ts ApiError?
- Delete the legacy non-router App.vue template and all top-level duplicate modules (and move their tests to core/), or keep them? App.test.ts depends on the legacy template.
- Brand: is exact hex (#f97316 base / #ea580c hover) required, which would mean changing primitives/Button.vue and primitives.test.ts? Or are Tailwind v4 orange-500/600 acceptable? And which shade is base vs hover?
- Will the backend send a SignalR event with a reason for access revocation (separate from device revocation), and a policy-changed event for refetching my-permissions?
