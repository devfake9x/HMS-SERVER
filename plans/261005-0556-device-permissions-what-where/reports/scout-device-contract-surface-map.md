## risks
- The approved design and the brainstorm say 45 firmware permissions, but the source has 46 (44 literal plus sys.config_export and sys.config_import, used only through config domains). Building the role-permission vocabulary from '45' would drop one key and make config.get or config.set{system} unauthorizable.
- Marking sys.ota as high-risk also makes the class R read ota.remote_config_get (cmd_descriptor.c:204) grantable only by master-admin, because it shares that permission with ota.remote_start and ota.apply.
- Several permissions span classes: wifi.scan (C start plus R results), mb_rtu.config_edit (W plus C restart), sys.time_edit (C plus W), broker.*_edit and wifi.known_edit (W plus D delete). The 'subset of own permissions' rule works on permission keys, so granting an edit key always includes the destructive row.
- Changing the catalog_hash canonicalization invalidates every client-held hash. Clients get CATALOG_STALE (SendDeviceCommandHandler.cs:59-66) until they reload, which is intended but must be rolled out with the frontend DTO change.
- Hashing a CRLF checkout of cmd_descriptor.c gives a different source_hash (19274b06…). Hash the git blob bytes.
- Generating from the device capabilities snapshot instead of the source loses confirm_template, accepts_body, audit_publish and outcome_deferred, and omits ttl_ms for rows with no default (cmd_descriptor.c:618-641).
- The firmware enforces no permission (command_dispatcher.c:625-637), so any server mapping error grants full device authority.
- The server currently would send ttl_ms=120000 for rows whose reviewed default is 60000 (24 rows incl. reboot/factory_reset/ota.apply), widening their validity window; firmware honours the envelope value.
- The domain must be read from Payload["domain"] as an exact string. Payload is IReadOnlyDictionary<string, object?>, so values may be JsonElement, and a loose ToString() could turn a number or object into a string. The firmware accepts strings only (cmd_descriptor.c:434).
